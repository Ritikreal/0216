# AL — Local-first voice assistant for Arch + Hyprland

AL is a local-first desktop assistant for Arch Linux + Hyprland. The Python CLI currently provides local speech recognition and spoken responses, and a native Quickshell HUD/workspace prototype is available. The HUD is not yet connected to the voice runtime or a general local AI model.

**[Read the roadmap and phase exit gates](docs/ROADMAP.md).**

## Current MVP

- Bounded microphone capture through PortAudio/PipeWire.
- RMS-energy speech detection with DC-offset removal.
- Local speech recognition with faster-whisper on CPU.
- A few safe phrase-based responses without an LLM.
- Local Kokoro ONNX speech output with the selected female `af_heart` voice.
- Tests ensuring unknown commands are not executed.

The voice loop has successfully captured and transcribed a short utterance on the target Arch laptop, and the microphone detection fix was reported working. The HUD/runtime bridge and desktop integration still need end-to-end validation.

## Principles

- Speech recognition stays local at runtime; no cloud transcription fallback.
- Models are loaded from local cache only. Download model files beforehand if needed.
- No arbitrary shell commands generated by a language model.
- Desktop actions will use explicit, testable skills with permission policies.
- Prioritize fast replies and a responsive HUD over minimizing CPU use at all costs.
- The HUD takes inspiration from a cinematic Peter Parker / Spider-Man engineering aesthetic without copying a film interface pixel-for-pixel.

## Install on Arch

```bash
sudo pacman -Syu
sudo pacman -S --needed base-devel python python-pip python-virtualenv portaudio pipewire pipewire-audio pipewire-pulse wireplumber git
```

Kokoro ONNX speech dependencies are installed with the project. Download its model and voice bundle separately using the voice setup guide.

From the repository directory:

```bash
python -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e . pytest
mkdir -p ~/.config/al ~/.local/bin ~/.local/state/al
install -m 0644 config/settings.toml ~/.config/al/settings.toml
```

## Test

```bash
.venv/bin/python -m pytest -q
wpctl status
python -c 'import sounddevice as sd; print(sd.query_devices())'
al --once
```

The first model download is a setup step. Once the selected model is cached, the runtime is configured for local-only loading. The model cache is normally under `~/.cache/huggingface`.

## Speech configuration

`config/settings.toml` defaults to the `base.en` model, CPU, and int8 compute. `tiny.en` may reduce latency at some cost to accuracy; `small.en` may improve accuracy at a higher resource cost. Benchmark on the target laptop before changing defaults.

To configure local spoken output, follow [the Kokoro voice setup guide](docs/VOICE_SETUP.md). It downloads the model and voice bundle explicitly; runtime TTS does not use cloud services.

## Current limitations

- Voice capture still uses the terminal Enter-to-talk workflow; no global hotkey is connected to the HUD.
- The Quickshell HUD is a visual/workspace prototype. Its chat, state chips, and activity stream are preview-only and do not call the assistant runtime.
- No general local LLM conversation or connected desktop-control skill is implemented.
- Kokoro generates a complete WAV before playback.
- The systemd unit is a template and must be reviewed against the actual installation path before use.

See [ui/README.md](ui/README.md) for the HUD's current features and [docs/ROADMAP.md](docs/ROADMAP.md) for the architecture, performance strategy, and safety boundaries.
